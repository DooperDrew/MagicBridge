# ADR 0001 — Rust for the agent and the settings GUI

- **Status:** Accepted (proposed by the assistant, owner said "you decide")
- **Date:** 2026-10-25

## Context
The top constraint is minimal resource usage and zero interference with other apps and games.
The app needs low-level Win32 access (keyboard hooks, Raw Input, HID, tray) and a small GUI.

## Options
| Option | RAM idle | Pros | Cons |
|---|---|---|---|
| **Rust** | ~2–5 MB | Native, no runtime, memory-safe, official `windows` crate, good GUI option (egui) | Steeper learning curve |
| C++ / Win32 | ~1–3 MB | Smallest, direct API | Memory-safety bugs are easy to make; GUI work is tedious |
| C# / .NET | ~20–40 MB | Fast to write, WinForms/WPF | Runtime overhead, GC pauses could affect the hook's latency |

## Decision
Rust for every component. The GUI is a **separate process** (egui), so its memory use never affects
the always-running agent.

## Consequences
- Build needs the Rust toolchain (MSVC target) and Visual Studio Build Tools.
- The hook code has to follow strict no-alloc/no-lock rules (enforced through code review + `AGENTS.md`).
