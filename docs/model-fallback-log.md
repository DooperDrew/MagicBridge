# Model Fallback & Retrospective Review Log

This document tracks all instances where an AI coding agent or worker had to execute a task using a **downgraded or fallback model** (e.g. falling back to a lower tier due to token budget constraints, rate limits, or quota unavailability).

Every logged entry is tracked as a pending retrospective verification item for the Lead Agent to audit once higher-tier capacity is available.

## Retrospective Audit Workflow

Whenever an entry is logged above:
1. **Log Entry Creation:** The Lead Agent logs the task, target model, fallback model, and the date/time.
2. **Backlog Audit Item:** The Lead Agent appends a retrospective verification item in `docs/05-roadmap.md` under Milestone 6 (Hardening & Quality Review).
3. **Audit Execution:** Once capacity is available, a higher-tier model (`pro` or `inherit`) reviews the code generated by the fallback model:
   - Check for missed edge cases or subtle performance degradations.
   - Verify compliance with performance budgets (NFR-P1…P5).
   - Assess whether the fallback model's output was optimal or required refactoring.
4. **Resolution:** Update the "Code Quality Audit Status" column to **`AUDITED & PASSED`** or **`REFACTORED`**.
